# cache-meter

Мод для Claude Code. Над полем ввода показывает размер контекста, сколько осталось жить кэшу промпта и лимиты подписки. Подсказывает, когда запрос обойдётся дорого, и ведёт статистику расхода по дням и проектам.

```
ctx ━━━━━━━━━━━━━━━━╌╌╌╌╌╌╌╌╌ 250k/1M (25%) · кэш 1h: 42:10 · hit 98% · 5ч 23% до 14:30 · 7д 41% до пт 10:00
```

## Полоса над промптом

Обновляется раз в секунду.

- **`ctx`** — сколько токенов уйдёт в следующий запрос. Линия — это путь до красного порога (по умолчанию 400k). Заполненная часть плавно меняет цвет: зелёный, к 200k жёлтый, к 300k оранжевый, к 400k красный. Пустая часть — тусклый пунктир цвета своей зоны, поэтому видно, где следующая граница. Когда контекст доходит до порога, вся линия краснеет: пора `/compact`. Шкала не привязана к окну в 1M, потому что качество ответов падает задолго до его заполнения. После сжатия размер показывается с `≈`, пока модель не ответит.
- **`кэш 1h: 42:10`** — сколько осталось жить кэшу. Отсчёт идёт от последнего запроса основного диалога, каждый запрос продлевает кэш. Когда срок выйдет, появится «истёк N мин назад» и сколько токенов следующий запрос запишет заново.
- **`hit 98%`** — какая доля последнего запроса пришла из кэша.
- **`5ч`, `7д`** — сколько израсходовано из 5-часового и недельного лимита подписки и когда сброс.
- **`агенты 2 (340k)`** — пока работают субагенты: сколько их и сколько токенов они обработали.

Клик по линии контекста открывает `/cache-meter`, клик по `7д` — `/cache-stats`. Нужен терминал с поддержкой мыши, команды работают и без неё.

## Под каждым ответом

Служебная строка, модель её не видит:

```
ответ: 14 запросов · кэш: чтение 1.8M / запись 35k · ввод 2k · вывод 6k · ≈190k вх.
```

`≈190k вх.` — цена ответа в токенах обычного ввода: чтение из кэша ×0.05, запись ×2, вывод ×5. Так ответы можно сравнивать между собой.

После `/compact` появляется строка `сжатие: 312k → ≈78k`.

## Вопросы перед дорогими действиями

- **Сообщение при истёкшем кэше.** Если кэш истёк, а контекст больше 100k, мод перед отправкой скажет, сколько сообщение запишет заново, и предложит: отправить, сжать и отправить или отменить. При отмене текст возвращается в поле ввода.
- **`/model` и `/effort` при живом кэше.** Смена модели или effort сбрасывает кэш. Если контекст больше 100k, мод спросит, стоит ли это записи всего контекста заново.

Пороги меняются в настройках, 0 отключает вопрос.

## Уведомления

- за 5 минут до истечения кэша — системное уведомление и всплывающее сообщение;
- «кэш потерян», если таймер ещё жив, а запрос почти не попал в кэш, с вероятной причиной: смена модели или effort, изменился CLAUDE.md или инструменты;
- результат инструмента больше 15k токенов: «Read UserController.php добавил в контекст ~22k»;
- файл прочитан третий раз за сессию.

## Продление кэша

`/keepalive` отправляет короткий запрос поверх всего диалога: префикс читается из кэша, и срок кэша начинается заново. В историю диалога запрос не попадает.

Автопродление срабатывает само за 2 минуты до истечения, но один раз. Следующее станет доступно после вашего сообщения, поэтому кэш не продлевается всю ночь, пока вас нет.

## Панели

**`/cache-meter`** — текущая сессия:
- рост контекста по ответам;
- из чего состоит контекст: системный промпт, инструменты, MCP по серверам, файлы памяти, переписка — как в `/context`, обновляется после каждого ответа;
- итоги сессии и субагенты;
- что принесли в контекст инструменты, самые большие результаты, повторно прочитанные файлы;
- самые дорогие и последние ответы, журнал потерь кэша.

**`/cache-stats`** — все сессии:
- сегодня, вчера, 7 и 30 дней: цена в токенах обычного ввода, ответы и запросы, hit, отдельно основной диалог, субагенты, продления и сжатия, потери кэша и сколько сэкономил кэш;
- расход по проектам за сегодня, 7 и 30 дней;
- по моделям: сколько ушло на Opus, Sonnet и Haiku за 7 и 30 дней, доля и hit;
- субагенты по типам за 30 дней: запуски, всего и в среднем за запуск — видно, какие агенты дороже и что выгоднее делать самому;
- по дням за две недели.

Статистика хранится локально в хранилище плагина 60 дней. Учёт начался с версии 0.7.0, разбивка по проектам — с 0.8.0, по моделям и типам субагентов — с 0.11.0.

## Команды

| Команда | Что делает |
|---|---|
| `/cache-meter` | Панель текущей сессии |
| `/cache-stats` | Статистика по дням и проектам |
| `/keepalive` | Продлить кэш сейчас |

## Установка

В Claude Code:

```
/plugin install cache-meter --marketplace Dmitry7917/cache-meter
```

Из терминала:

```
claude plugin install cache-meter --marketplace Dmitry7917/cache-meter
```

Обновление до новой версии:

```
claude plugin update cache-meter@dmitry-mods
```

затем `/reload-plugins`. Что изменилось — в [релизах](https://github.com/Dmitry7917/cache-meter/releases).

## Настройки

Меняются в `/config`, строки cache-meter. Размеры — в тысячах токенов.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| Prompt cache TTL | `1h` | TTL кэша: `1h` на подписке, `5m` при оплате сверх лимита и в API |
| Context: yellow / orange / red from | 200 / 300 / 400 | Пороги зон контекста; красный порог — конец линии |
| Warn before cache expiry | 5 | За сколько минут предупредить об истечении кэша, 0 выключает |
| Auto keepalive | вкл. | Автопродление кэша, один раз на каждое ваше сообщение |
| Auto keepalive before expiry | 2 | За сколько минут до истечения продлевать |
| Ask before sending over an expired cache from | 100 | С какого контекста спрашивать перед отправкой при истёкшем кэше, 0 выключает |
| Ask before /model or /effort from | 100 | С какого контекста спрашивать перед сменой модели или effort при живом кэше, 0 выключает |
| Warn on tool results over | 15 | Порог большого результата инструмента, 0 выключает |
| Warn when a file is read this many times | 3 | После скольких чтений одного файла предупредить, 0 выключает |

## Ограничения

- TTL кэша движок не сообщает, он задаётся настройкой. Если сессия перейдёт на оплату сверх лимита и TTL станет 5m, таймер будет показывать больше, чем есть. Выдаст это низкий hit после короткой паузы.
- Размер после сжатия и состав контекста — оценки, как в `/context`. Точный размер приходит с первым ответом модели.
- Токены результатов инструментов оцениваются по длине текста, около 4 символов на токен. Для русского текста оценка занижена.
- Причину потери кэша мод угадывает: смену модели и effort видит точно, остальное — предположение.
- Цена в «вх.» посчитана по ценам Opus с TTL 1h. У других моделей соотношения другие.
- Чтения и вызовы субагентов попадают в их собственный контекст, мод считает только их общую сумму токенов.
